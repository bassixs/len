# Проект «Лён» — обзор и статус

Документ описывает, что это за проект, как устроен фронтенд, какая была проделана работа по очистке и интеграции с WooCommerce, и какие шаги логично сделать дальше. Актуально на **март 2026**.

---

## 1. Что это за проект

**Интернет-витрина магазина льняной одежды и текстиля** — многостраничный статический фронтенд на **Vite**, визуально и по структуре близкий к готовому сайту: главная, каталог, категории, карточка товара, корзина, контакты, доставка, блог, услуги и др.

Изначально каталог и карточки опирались на **локальные JSON** в `public/data/`. Сейчас целевая схема — **headless-режим**: данные о товарах берутся из **WooCommerce** по **REST API**, а этот репозиторий — фронтенд, который подключается к уже существующему магазину на WordPress/Woo.

Репозиторий: [github.com/bassixs/len](https://github.com/bassixs/len) (см. `package.json`).

---

## 2. Технологии и структура

| Компонент | Назначение |
|-----------|------------|
| **Vite 7** | Сборка, dev-сервер, мультистраничный вход (`index.html`, `catalog.html`, …). |
| **vite-plugin-handlebars** | Подключение общих блоков из `partials/` (шапка, подвал, модалки). |
| **ES-модули** | Логика в `js/modules/*.js`, точка входа `js/main.js`. |
| **Vitest + happy-dom** | Юнит- и дымовые тесты в `js/modules/__tests__/`. |
| **ESLint + Prettier** | Линт и форматирование. |

Основные страницы задаются в `vite.config.js` в `build.rollupOptions.input`. Статика отдаётся из `public/` (в т.ч. `public/data/`, `public/images/`).

## 3. Интеграция с WooCommerce

### Переменные окружения

Файл **`.env.example`** в корне — шаблон. Рабочие значения копируют в **`.env.local`** (обычно не коммитят).

| Переменная | Роль |
|------------|------|
| `VITE_USE_WOO=true` | Включить загрузку каталога и карточек из Woo вместо статического JSON (где это уже реализовано). |
| `WOO_ORIGIN` | Базовый URL сайта с Woo (без слэша в конце), например `https://example.ru`. |
| `WOO_CONSUMER_KEY` / `WOO_CONSUMER_SECRET` | Ключи REST API WooCommerce (права **чтения** достаточно для каталога). |

### Прокси в dev

В **`vite.config.js`** настроен прокси: запросы с фронта идут на **`/api/wc/...`**, dev-сервер переписывает их в `WOO_ORIGIN/wp-json/wc/v3/...` и **подставляет ключи на стороне сервера**, чтобы они не попадали в клиентский бандл.

Модули **`js/modules/woo-client.js`** (запросы к `/api/wc`) и **`js/modules/woo-map.js`** (приведение ответа Woo к полям карточки) поддерживают этот режим.

### Где уже используется Woo

- **`catalog.html`** — при `VITE_USE_WOO=true` список товаров подтягивается через `fetchAllWooProducts()` в **`js/modules/catalog.js`**.
- **`product.html?woo=<id>`** — карточка товара по ID в Woo (логика в **`js/modules/product.js`**).

### Важно для production

В **браузере на проде нет Vite-прокси**. Нужен **обратный прокси** (nginx, Cloudflare Worker, отдельный маленький backend и т.п.), который по пути вроде `/api/wc` проксирует на WordPress и добавляет ключи **только на сервере**. Или вынос API на backend с секретами — но публично ключи не светить.

## 4. Что сделано за время работ (эволюция репозитория)

Ниже — сводка по смыслу, без привязки к отдельным коммитам.

### 4.1. Роль данных и очистка

- Зафиксирован принцип: **источник правды по товарам — WooCommerce**, а не дубли в репозитории. Удалять товары нужно в админке Woo, а не «чистить» их только в git.
- **Демо-данные в JSON сокращены**: `public/data/products/*.json` и **`public/data/categories.json`** приведены к **минимальным заглушкам** (пустые или почти пустые массивы товаров, но сохранены заголовки категорий и фильтры там, где это нужно верстке).
- Удалены **дубликаты и тяжёлые артефакты импорта**:
  - папка **`импорт/`** (CSV выгрузки Bitrix/Woo для импорта — для работы сайта не нужны);
  - папка **`scripts/`** (Python/Node-утилиты: конвертация CSV, merge, скрапинг — сайт их не вызывает).
- В **`public/images/`** удалены вложенные папки **`catalog/`** и **`products/`** — на них **не ссылался код**; это были массовые локальные картинки под старый статический каталог. Корневые изображения интерфейса (коллекции, hero, иконки) **сохранены** по запросу не трогать общую папку `images` целиком.

### 4.2. Headless-режим

- Настроен **прокси** и клиент к **Woo REST API**.
- Каталог на **`catalog.html`** и карточка по **`product.html?woo=ID`** могут работать от живого магазина при корректном `.env.local`.

### 4.3. Ограничения после очистки (важно понимать)

- **`category.html`** и связанный **`category-products.js`** по-прежнему ориентированы на **`data/products/{категория}.json`**. После обнуления статики **списки на страницах категорий пустые**, пока не подключить Woo (или не вернуть данные в JSON).
- **`index.json` / превью на главной** — в упрощённом виде; слайдеры/блоки, завязанные на превью из JSON, без доработки могут показывать пусто.
- Старые ссылки **`product.html?id=...`** к маппингу из статического `index.json` **могут не работать**, если маппинг пустой; рабочий путь для Woo — **`?woo=<id>`**.

## 5. Ключевые модули (кратко)

| Файл | Назначение |
|------|------------|
| `js/main.js` | Подключает `init*` только на нужных страницах. |
| `js/modules/catalog.js` | Каталог: Woo **или** `data/products/index.json`. |
| `js/modules/category-products.js` | Категория: пока в основном статический JSON по slug. |
| `js/modules/product.js` | Карточка: Woo по `woo=` **или** старый путь по `id` + JSON. |
| `js/modules/product-cards.js` | Обогащение карточек на главной и др. из JSON. |
| `js/modules/cart.js` / `cart-service.js` | Корзина в браузере (локальное состояние; синхронизация с Woo отдельной задачей). |
| `js/modules/product-model.js` | Нормализация товара, цены, картинок. |

Более старый модульный разбор (частично устарел по данным) остаётся в **`CURRENT_POSITION.md`**; актуальная «картина мира» — в этом файле.

## 6. Что делать дальше (рекомендуемый порядок)

1. **Страница категории (`category.html`)** — загружать товары из Woo по **ID или slug категории** Woo, сопоставив их с slug в URL сайта (или передавать `woo_cat=` в query). Это вернёт наполнение разделов без тяжёлых JSON.
2. **Главная** — превью «хиты / новинки» с Woo (отдельные запросы или теги/категории), чтобы не зависеть от пустого `index.json`.
3. **Production** — настроить **серверный прокси** для `/api/wc` с теми же правилами, что в Vite, либо BFF с секретами.
4. **Корзина и оформление** — при необходимости **WooCommerce Store API** или собственный backend; текущая корзина в основном клиентская.
5. **Безопасность** — ключи REST только в `.env.local` / сервере; при утечке в переписке — **отозвать и перевыпустить** в Woo.

## 7. Локальный запуск

```bash
npm install
cp .env.example .env.local
# Заполнить WOO_ORIGIN, WOO_CONSUMER_KEY, WOO_CONSUMER_SECRET, VITE_USE_WOO=true
npm run dev
```

Сборка: `npm run build`, предпросмотр: `npm run preview`.

## 8. Связанные файлы в репозитории

- `vite.config.js` — прокси Woo, точки входа HTML.
- `.env.example` — шаблон переменных.
- `public/data/` — облегчённые JSON для fallback и метаданных категорий.
- `public/images/` — ассеты интерфейса (не дубль медиатеки товаров Woo).

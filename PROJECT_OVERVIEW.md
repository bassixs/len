# Проект «Лён» — обзор и актуальный статус

Документ фиксирует текущее состояние проекта как headless-витрины поверх WooCommerce. Актуально на **март 2026**.

---

## 1. Что это за проект

Многостраничный фронтенд на **Vite** с кастомной версткой (`index`, `catalog`, `category`, `product`, `cart` и др.), который в рабочем режиме берет товарные данные из **WooCommerce REST API**.

Текущая целевая модель:

- фронт в этом репозитории;
- WordPress + WooCommerce как источник данных по товарам;
- обмен через API-слой `'/api/wc'`.

## 3. Что работает сейчас

### 3.1 Woo-режим (основной)

- `catalog.html` — товары из Woo (не из локальных JSON).
- `product.html?woo=<id>` — карточка товара из Woo.
- `category.html` — товары категории из Woo + фильтры/сортировка/цена/пагинация.
- карточки на главной (`product-cards`) в Woo-режиме также подгружаются из API.

### 3.2 Маппинг категорий

Для стабильной работы на проде используется фиксированное сопоставление `cat` из URL к ID категорий Woo:

- `home-textile -> 24`
- `women -> 370`
- `men -> 352`
- `socks -> 567`
- `gifts -> 592`
- `accessories -> 16`
- `fabrics -> 654`

Плюс есть гибкий fallback по slug/alias/названию категорий.

### 3.3 Производительность листингов

Для списков используется запрос с ограничением полей (`_fields`), чтобы не тянуть тяжелые описания в каталоги и категории.

## 4. Как устроен API-слой

### Локально (dev)

В `vite.config.js` настроен прокси `'/api/wc' -> '/wp-json/wc/v3'` с подстановкой ключей на стороне dev-сервера.

### На production

Vite-прокси отсутствует, поэтому `'/api/wc'` проксируется на сервере (в текущем стенде — через `.htaccess` rewrite).

Важно: текущая схема с ключами в rewrite годится как временное решение, но безопаснее вынести в отдельный backend/BFF и не светить ключи в URL.

## 5. Что было очищено в репозитории

- Статические JSON-данные каталога существенно урезаны (fallback/заглушки).
- Удалены массивные неиспользуемые локальные каталоги изображений старого статического каталога.
- Удалены вспомогательные импортные/скриптовые артефакты, не влияющие на работу сайта.

Идея: единственный источник правды по товарам — Woo, а не дубли в git.

## 6. Ключевые модули

| Файл                                    | Назначение                                          |
| --------------------------------------- | --------------------------------------------------- |
| `js/modules/woo-client.js`              | запросы к `'/api/wc'`, загрузка товаров и категорий |
| `js/modules/woo-map.js`                 | маппинг ответа Woo в формат карточек/страниц        |
| `js/modules/catalog.js`                 | каталог (Woo + fallback)                            |
| `js/modules/category-products.js`       | категория, фильтры и маппинг `cat -> woo`           |
| `js/modules/product.js`                 | карточка товара и related                           |
| `js/modules/product-cards.js`           | подгрузка товарных карточек на главной/слайдерах    |
| `js/modules/cart.js`, `cart-service.js` | клиентская корзина                                  |
| `js/modules/product-model.js`           | нормализация товара/цены/изображений                |

## 7. Что осталось сделать (приоритет)

1. Перевести API-ключи из публичного rewrite в серверный BFF/прокси без утечки в URL.
2. Выпустить новые Woo REST ключи (текущие уже светились в процессе отладки).
3. Зафиксировать и поддерживать карту категорий Woo как конфиг (при изменениях в Woo).
4. Решить стратегию checkout: текущая корзина локальная, полноценный поток заказа через Woo Store API пока не реализован.
5. Добавить короткий `DEPLOY.md` с чеклистом выкладки и smoke-тестов.

## 8. Локальный запуск

```bash
npm install
cp .env.example .env.local
# заполнить WOO_ORIGIN, WOO_CONSUMER_KEY, WOO_CONSUMER_SECRET, VITE_USE_WOO=true
npm run dev
```

Сборка: `npm run build`  
Проверка сборки: `npm run preview`

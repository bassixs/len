# Текущее положение проекта (март 2026)

## Коротко

Проект находится в рабочем состоянии как **headless-витрина на Vite** с **WooCommerce REST API** в роли источника данных (`/api/wc`).

Источник правды по товарам и категориям — Woo. Локальные JSON в `public/data/` используются как fallback для legacy-сценариев.

## Текущий статус

- `catalog.html` работает от Woo (постраничная загрузка + сортировка).
- `category.html` работает от Woo (фильтры, сортировка, цена, подкатегории, пагинация).
- `product.html?woo=<id>` рендерит карточку из Woo + related товары.
- `new.html` и карточки на `index.html` подгружаются из Woo.
- На карточках и странице товара отображается статус наличия:
    - `В наличии`
    - `Нет в наличии` + блокировка действий покупки.

## Категории и счетчики (актуальная логика)

- Базовый выбор Woo-категории идет **динамически**: по `woo_cat` из URL (если передан), затем по slug/alias/названию.
- Для неоднозначных совпадений выбирается категория с максимальным `count`.
- Если API не присылает `X-WP-Total`, категории всё равно догружаются до конца страницами по 100 записей.
- Из-за этого счетчики и вкладки подкатегорий сходятся с данными Woo после полной фоновой догрузки.

## Важные оговорки

- На проде Vite-прокси отсутствует: `/api/wc` должен проксироваться сервером.
- Сейчас это реализовано через `.htaccess` rewrite (рабочее, но временное решение).
- Woo REST ключи, которые светились при отладке, должны быть перевыпущены.
- Checkout пока не интегрирован с Woo Store API: корзина клиентская (localStorage).

## Что уже можно считать завершенным

- Основные страницы витрины (catalog/category/product/new/home cards) работают от Woo.
- Счетчики категорий и вкладки подкатегорий синхронизированы с Woo через догрузку всех страниц.
- Статус наличия отображается визуально и влияет на действия покупки.
- `npm run build` и линт по изменяемым файлам проходят стабильно.

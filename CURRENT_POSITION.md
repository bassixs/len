# Текущее положение проекта (март 2026)

## Коротко

Проект работает как headless-витрина на Vite с WooCommerce REST API в роли источника данных (`/api/wc`).
Woo является source of truth для каталога, категорий, карточек товара и наличия.

## Текущий статус

- `catalog.html` переведен в формат страницы-разделителя: показывает карточки категорий (без общего листинга товаров).
- `category.html` работает от Woo: корректный выбор root-категории, фильтры, сортировка, цены, сабкатегории, load more.
- `product.html?woo=<id>` работает от Woo: новая галерея со стрелками, улучшенный UX описания, related товары.
- `new.html` и блок "Лучшие предложения" на `index.html` подгружаются из Woo.
- В "Лучших предложениях" показываются только товары `in stock`; статические заглушки не отображаются при пустом/ошибочном ответе Woo.
- Наличие (`В наличии` / `Нет в наличии`) отображается на карточках и в карточке товара, кнопки покупки блокируются для out-of-stock.

## Последние важные изменения

- Полный визуальный refresh `services.html` (современный hero, карточки форматов пошива, обновленный процесс и CTA).
- Серьезный UX-апдейт `product.html`:
  - стрелки галереи + клавиатурная навигация,
  - блок действий (qty/add/wishlist) под фото,
  - сворачиваемое длинное описание (`Показать полностью`),
  - отдельный аккуратный блок "Подробное описание".
- Улучшено качество главной фотографии товара: для `product.html` выбирается наиболее качественное изображение из Woo `images`.
- Ускорение загрузки карточки товара:
  - `fetchWooProduct` переведен на общий кэш/дедупликацию,
  - запрос ограничен `_fields` (меньше payload).
- Добавлен page-level code splitting в `js/main.js` (ленивая загрузка модулей по факту страницы).
- Добавлены skeleton-состояния для `category` и `product` (меньше визуальной задержки).
- Добавлен prefetch Woo-товара перед переходом из листингов:
  - при `pointerdown` / `focusin` / `touchstart`,
  - с защитой от перегрузки сети (убран агрессивный `pointerenter`).
- Для сценария "большая категория -> сразу в товар" добавлен hint cache:
  - базовые данные товара передаются через `sessionStorage`,
  - карточка товара показывается мгновенно до полной догрузки.
- Hint cache ограничен по размеру и TTL (cleanup/LRU-подобное поведение).
- Для тяжелых категорий внедрен staged loading:
  - быстрый first paint по root-категории,
  - фоновое расширение дочерними категориями с задержкой.
- Исправлен регресс по категориям:
  - восстановлена корректная логика `Показать ещё`,
  - поправлен расчет total при отсутствии `X-WP-Total`.
- `api-wc-proxy.php` исключен из git через `.gitignore` (локальный файл с секретами).

## Категории и счетчики

- Базовый выбор Woo-категории: `woo_cat` из URL -> slug/alias/name -> выбор категории с максимальным `count`.
- Для полноты выборки учитываются дочерние категории выбранного root.
- При отсутствии `X-WP-Total` используется fallback-логика, чтобы итоговые счетчики и пагинация сходились с Woo.

## Важные оговорки

- На проде нет Vite proxy: `/api/wc` должен проксироваться сервером.
- Текущий вариант проксирования рабочий, но рекомендуется перейти на полноценный backend/BFF без передачи секретов в query.
- Корзина пока клиентская (`localStorage`), checkout flow с Woo Store API еще не внедрен.
